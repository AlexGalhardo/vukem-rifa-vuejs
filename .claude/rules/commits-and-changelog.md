# Commits and changelog

- Conventional Commits (commitlint, scopes in `commitlint.config.js`), English, imperative. The commit message is the changelog entry: `feat` → Added, `fix` → Fixed, `refactor`/`perf` → Changed, `build(deps)` (vukem bumps) → Changed, a body mentioning security → Security; `docs`/`test`/`ci`/`build`/`chore`/`style` are left out.
- `CHANGELOG.md` (Keep a Changelog 1.1.0) is generated by git-cliff (`cliff.toml`) and links every entry to its commit. Never edit it by hand.
- Releasing: `git cliff --tag vX.Y.Z -o CHANGELOG.md`, commit `chore(release): vX.Y.Z`, annotated tag `vX.Y.Z` on that commit, push the commit and the tag; `.github/workflows/release.yml` builds the GHCR image and publishes the GitHub release with that version's section.
- SemVer: one minor per milestone (finished PLAN.md phase, vukem bump, deploy); `v1.0.0` at launch. Never move a pushed tag.
